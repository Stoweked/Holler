# `src/lib/maple` — the maple data layer

Everything this app reads from the `maple` service goes through here.

| File | Role |
|---|---|
| `schema.d.ts` | **Generated.** TypeScript types for maple's HTTP API. Never hand-edit. |
| `client.ts` | The only place a maple request is constructed. Attaches the Cognito bearer token. |
| `result.ts` | `Result<T>` — success carrying `data`, transport failure carrying none. |
| `adapter.ts` | Maps maple's `Transfer` onto the frontend's `Transaction`. |

Implements [SPEC 13](https://github.com/franklinCarson/hollermeta/blob/master/specs/13-frontend-maple-data-layer.md) in the `hollermeta` repo.

## Where `schema.d.ts` comes from

Generated by [`openapi-typescript`](https://openapi-ts.dev) from maple's OpenAPI
document — the same file maple generates its own server from, so it is the
contract's single source of truth.

- **Source repo:** `maple`
- **Path in that repo:** `openapi/api.yaml`
- **Generated from maple commit:** `1d006f3a68c69ec476da659ab0ad5778c608b967`

**The spec is deliberately not vendored into this repo.** A copy here would rot
silently against maple, and `verify:api-types` would then only prove the
generated types match a stale copy — a gate guarding the wrong thing. Pointing
generation at maple directly means the check compares against the real contract.

Update the commit SHA above whenever you regenerate.

## Regenerating

Requires a `maple` checkout. In the Foreman workspace both repos are worktrees
side by side, so the default path resolves with no configuration:

```sh
npm run generate:api                              # uses ../maple/openapi/api.yaml
MAPLE_API_SPEC=/path/to/maple/openapi/api.yaml npm run generate:api
```

## Drift check

```sh
npm run verify:api-types
```

Regenerates and fails if the committed `schema.d.ts` differs — catching both a
hand-edit here and an API change in maple that has not been pulled through.

**This is a developer gate, not a CI gate.** It needs a `maple` checkout, so it
cannot run in a standalone build (Vercel, CI). It does not fail quietly there —
generation errors and the script exits non-zero — so simply do not wire it into
CI. Run it locally when touching this directory or after maple's API changes.

The long-term fix is for maple to publish its generated TypeScript types as a
versioned package, which this repo would depend on like any other dependency.
Until then, this check is the drift protection, and it only runs where both
repos are checked out.
